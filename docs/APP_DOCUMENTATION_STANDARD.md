# App 文档规范

每个 `apps/<app-id>/README.md` 都是该应用的中文入门入口。它必须能脱离单仓直接阅读，因而不能依赖只存在于根仓库的相对链接；导出为 Git subtree 后仍要保留构建、架构和扩展说明。

## 必备章节

README 必须按以下顺序保留章节：

1. `应用目标与边界`：用户价值、模拟能力、尚未接入的真实硬件或协议。
2. `快速运行`：PC SDL2、Linux fbdev/evdev、测试和独立导出应用的命令。
3. `总体架构`：运行时、端口、UI、Application、Domain 与外部系统的 Mermaid 图。
4. `代码架构`：目录职责及依赖方向的 Mermaid 图。
5. `运行与交互流程`：事件到业务状态、ViewModel 和渲染回流的 Mermaid 时序图。
6. `代码地图`：推荐阅读顺序与关键文件职责。
7. `分层原理`：语义动作、ViewModel、纯 C Domain 与 LVGL UI 的解耦理由。
8. `新功能开发流程`：新增页面或业务能力时必须同步修改的层与测试。
9. `平台移植、资源与排错`：配置档、板级替换点、素材归属和高频故障。

## 图表与写作要求

- 至少保留三段 `mermaid` 代码块：总体架构、代码架构、交互时序图；交互图必须使用 `sequenceDiagram`。
- 图中的名称必须对应实际模块、动作和状态，不可长期保留“示例”“待补充”等占位描述。
- 构建命令必须同时说明单仓模式与导出应用模式的区别；外部框架版本以 `framework_lock.cmake` 为准。
- 说明 UI 只能发出语义动作，Application 负责映射，Domain 不包含 LVGL/平台头文件这一边界。

## 更新时机与检查

新增页面、语义动作、ViewModel 字段、平台目标、定时/外部事件或素材时，必须在同一提交更新该 App README。CI 使用 `cmake/ValidateAppDocs.cmake` 校验文件、标题、九个章节和 Mermaid 图表是否存在；代码评审负责验证说明与实现一致。
